# وحدة الطلبات

تملك هذه الوحدة نموذج طلب الخدمة وصفحة **طلباتي**، وتتعامل مع Firestore من خلال `src/features/requests/requestsService.js` فقط. لا تُحفظ خانة الموافقة `consent` في الوثيقة؛ فهي قرار واجهة المستخدم، بينما تُحفظ الحقول المعتمدة في العقد: `userId`, `serviceId`, `serviceTitle`, `name`, `email`, `contact`, `details`, `preferredDate`, `status`, و`createdAt`.

## السلوك الأمني

كل عملية قراءة أو إلغاء تتطلب مستخدمًا حقيقيًا وتستخدم معرّف الحساب. قواعد `firestore.rules` تمنع قراءة طلبات الآخرين، وتسمح بإنشاء طلب `pending` صالح فقط، وتسمح بتحويل `pending` إلى `cancelled` دون تعديل أي حقل آخر. الحذف ممنوع. الاستعلام يستخدم `where('userId', '==', uid)` ثم يرتب النتائج على العميل، لذلك لا يحتاج فهرسًا مركبًا.

## حالات الواجهة

تظهر الخدمة غير المعروفة كحالة عدم العثور. المستخدم غير المسجل يُوجَّه إلى تسجيل الدخول الحقيقي. عند غياب إعدادات `VITE_FIREBASE_*` تظهر رسالة إعداد صريحة ولا تُعرض بيانات وهمية ولا نجاح مختلق. لا تُعلن صفحة الطلب نجاحًا إلا بعد عودة معرّف فعلي من `addDoc`، ويُعطّل الإرسال أثناء الطلب. صفحة **طلباتي** تعرض حالات التحميل، الفراغ، الخطأ، و`pending`/`cancelled` فقط.

## التشغيل المحلي

استخدم مشروع Firebase الوهمي `demo-student-marketplace` مع محاكي Firestore على `127.0.0.1:8080`. اختبار القواعد اختياري ومقصود به المحاكي فقط؛ شغّله بعد تفعيل `RUN_FIREBASE_RULES_TESTS=1` و`FIRESTORE_EMULATOR_HOST`. لا تُضع مفاتيح Firebase أو ملفات `.env` في المستودع.
