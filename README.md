# سوق خدمات الطلبة

مشروع Web Development I: سوق عربي للخدمات الجامعية باستخدام React وVite وFirebase Authentication وCloud Firestore. الواجهة RTL ومتجاوبة مع الهاتف والكمبيوتر. الكتالوج يحتوي 12 خدمة توضيحية في الدروس الخصوصية والتصميم والطباعة، مع بحث بالاسم والتصنيف وترتيب الأسعار وتفاصيل الخدمة ونموذج طلب.

الخدمات ومقدموها في `src/data/services.js` بيانات تركيبية للتوضيح، والأسعار بالجنيه المصري وليست عروضًا حقيقية. عناوين `.example` ليست وسائل تواصل تشغيلية. الحساب المسجل وملفه وطلباته يستخدمون Firebase الحقيقي؛ لا يوجد دخول وهمي أو رسالة نجاح عند فشل الحفظ. لا توجد مدفوعات أو محادثات أو لوحة إدارة للكتالوج ضمن نطاق التكليف.

## التشغيل المحلي

يلزم Node.js 22.20 أو أحدث من فرع 22، وpnpm 11.25.0:

```bash
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

ضع قيم Firebase Web app في `.env.local`، وأبقِ `VITE_PORTABLE_ASSETS=true` لاستخدام الصور المرفقة. يعمل خادم التطوير على المنفذ 3000. `.env.local` مستبعد من Git. لا تضع كلمات مرور أو Service Account أو Admin SDK private keys في React؛ كل قيمة تبدأ بـ`VITE_` تُضمّن في المتصفح، ولا تصلح للأسرار الخاصة.

بدون إعداد Firebase يمكن تصفح الكتالوج والبحث، وتظهر رسالة عدم جاهزية في تسجيل الدخول والطلب. إضافة قيم SDK وحدها لا تفعّل Authentication أو تنشئ Firestore؛ راجع [دليل Firebase والنشر](docs/DEPLOYMENT_AR.md).

## الصفحات العشر

1. `/` — تعريف بالسوق، بحث سريع، التصنيفات والخدمات المميزة.
2. `/services` — قائمة الخدمات والبحث والترشيح والترتيب.
3. `/categories` — صفحة مستقلة للتصفح حسب التصنيف.
4. `/search` — نتائج `q` و`category` و`sort` وحالة عدم وجود نتائج.
5. `/services/:serviceId` — وصف الخدمة وسعرها ومقدمها ومعلومات التواصل.
6. `/request/:serviceId` — نموذج طلب مرتبط بالخدمة؛ يلزم تسجيل الدخول والتحقق من المدخلات قبل الحفظ.
7. `/login` — تسجيل الدخول الحقيقي والعودة لمسار الطلب عند الحاجة.
8. `/register` — إنشاء الحساب وحفظ ملفه مع معالجة فشل حفظ الملف بعد نجاح إنشاء الحساب.
9. `/my-requests` — طلبات الحساب الحالي وإلغاء الطلب المعلّق بعد تأكيد Firestore.
10. `/students/:studentId` — ملف مقدم تجريبي عام، أو الملف الخاص للحساب الحقيقي وتعديل الاسم والكلية.

المعرفات غير المعروفة والمسارات غير الموجودة لها رسائل وخيارات رجوع. `public/manus-routes.json` يسجل مسارات الصفحات ولا يحتوي بيانات مستخدمين.

## الاختبارات والبناء

```bash
pnpm test
pnpm test:rules
pnpm build
pnpm preview
```

اختبارات القواعد تحتاج Java 21 أو أحدث، وتستخدم محاكيًا محليًا بمعرّف `demo-student-marketplace` وليس قاعدة المستخدم السحابية. التشغيل العادي يتخطى اختبارات المحاكي عمدًا؛ الأمر المنفصل يشغّلها فعليًا. `pnpm preview` يعرض البناء محليًا ولا ينشره. النتائج الفعلية في [تقرير المراجعة](docs/REVIEW_AR.md)، وCI يعيد تشغيل الوحدة والمحاكي والبناء عند push وpull request على main.

## تنظيم المشروع وتوزيع الفريق

`src/pages` للصفحات، و`src/components` للتخطيط والمكونات المشتركة، و`src/services` لدوال الحساب والملف والبحث والطلبات. `src/firebase.js` يجهز الاتصال، و`src/context/AuthContext.jsx` يشترك في حالة الحساب، و`src/hooks/useAuth.js` يتيح استخدامها في الصفحات. `src/utils/validators.js` يجمع التحقق، و`src/styles` للتنسيق، و`tests` للاختبارات، و`firestore.rules` لحماية البيانات.

للقراءة لأول مرة: ابدأ بـ`main.jsx` ثم `App.jsx` ثم `router.jsx`، وبعدها اقرأ `HomePage.jsx` و`ServicesPage.jsx` قبل صفحات الحساب والطلبات. [دليل فهم الكود المبسط](docs/BEGINNER_AR.md) يشرح useState وuseEffect وأحداث الفورم وترتيب البحث. الدوال واضحة والملفات أقرب لبعض؛ لم تُضف أخطاء متعمدة ولم تُضعف الحماية لتقليل التعقيد.

الأدلة: [أحمد عيد — الحساب والملف](docs/modules/auth_AR.md)، [ياسمين رجب — التخطيط والواجهة](docs/modules/layout_AR.md)، [ياسمين حسن — الكتالوج والبحث](docs/modules/services_AR.md)، [مريم مصطفى — الطلبات والتحقق](docs/modules/requests_AR.md)، [مصطفى أحمد — المراجعة والتكامل](docs/REVIEW_AR.md). نسبة الـcommits للحسابات توثق توزيع المشروع، ولا تُثبت أن الطلاب نفذوا الاختبارات بأنفسهم. كل طالب مطالب بفهم الجزء المرتبط به وشرحه وتعديله وتشخيص أعطاله.

## النشر والتسليم

الموقع المنشور: [سوق خدمات الطلبة](https://student-services-marketplace.vercel.app). نُشر على Vercel وتحقق فتحه دون تسجيل دخول. حفظ الملفات الشخصية والطلبات السحابي لم يكتمل بعد، لعدم إنشاء Firestore ونشر القواعد؛ راجع الحالة الفعلية قبل تجربة التسجيل والطلب.

`vercel.json` يحدد Vite و`dist` ويحافظ على الروابط الداخلية عند فتحها مباشرة. الصور مرفقة في `public/images` وتُفعّل خارج منصة التطوير بمتغير البيئة العام `VITE_PORTABLE_ASSETS=true`. [دليل النشر](docs/DEPLOYMENT_AR.md) و[الحالة الفعلية](docs/STATUS_AR.md) يفصلان التعليمات عن التنفيذ المثبت.

اختير Vercel بطلب صاحب المشروع. التكليف الأصلي يشترط سيرفر الجامعة؛ Vercel لا يثبت استيفاء هذا الشرط إلا إذا قبل المدرس البديل. يمكن رفع `dist` على السيرفر الجامعي مع SPA fallback وbase path المناسب، لكن لا يوجد نشر جامعي مثبت هنا.
